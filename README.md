# Асинхронный сервис для Оплаты заказов

## Реализованный функционал

| Функционал                                                                      | Реализация                                                 |
|---------------------------------------------------------------------------------|------------------------------------------------------------|
| Создание аккаунта с балансом                                                    | `Api Gateway -> Payment Service (Account)`                 |
| Получение информации об аккаунте/аккаунтах                                      | `Api Gateway -> Payment Service (Account)`                 |
| Пополнение баланса или снятие с баланса денег                                   | `Api Gateway -> Payment Service (Account)`                 |
| Создание заказа и передача события через Kafka                                  | `Api Gateway -> Order Service -> Kafka -> Payment Service` |
| Обработка создания заказа(Асинхронной снятие денег со счета, если это возможно) | `Kafka -> Payment Service -> Kafka`                        |
| Получение результата обработки заказа                                           | `Payment Service -> Kafka -> Order Service`                |

## Примененные архитектурные принципы

### Clean Architecture

| Принцип                      | Реализация                                     |
|------------------------------|------------------------------------------------|
| Слоистая архитектура         | `model`, `controller`, `service`, `repository` |
| Зависимости внутрь           | `model` не зависит от других слоев             |
| Изоляция бизнес-логики       | Вся логика в Model и Service слоях             |

### Микросервисная архитектура

| Модуль/Сервис            | Ответственность                                                                                             |
|--------------------------|-------------------------------------------------------------------------------------------------------------|
| Api Gateway              | Принимает запросы со стороны клиента и перенаправляет в необходимые сервисы                                 |
| Payment(Account) Service | Отвечает хранение информации об аккаунте пользователя, включая баланс. Также отвечает за обработку платежей |
| Order Service            | Отвечает за создание заказа, отправку события создания и получения результата платежа                       |
| Common                   | Общие сущности, например dto...                                                                             |
| Kafka                    | Брокер сообщений для общения между Order Service и Payment Service                                          |


## Технологический стек

- **Язык**: Java 17
- **Фреймворк**: Spring Boot 3
- **База данных**: PostgreSQL
- **Брокер сообщений**: Kafka

## Как запустить проект

1. Клонировать репозиторий
2. Запустить Docker Desktop(Docker daemon)
3. Собрать проект локально с помощью `mvn clean install`
4. Из корня проекта выполнить `docker compose up --build`
5. Протестировать через Postman (Импортировать Async Order Service API.postman_collection.json из корня проекта в Postman)


## По критериям

- Реализация основных требований и сценария. Сценарий реализован в соответствии с ТЗ(картинка в конце)
- Функциональность распределена по микросервисам(см. таблицу `Микросервисная архитектура`), ошибки Service Unavailable обрабатываются корректно (30 секунд таймаута)
- Kafka использована корректно - для публикации ивентов между микросервисами.
- Были применены паттерны Transactional Inbox в Payment Service и Transactional Outbox в Payment Service и Order Service
- Обеспечена семантика exactly once в продюсерах(см конфигурацию), атомарность списания денег.
- Реализована коллекция Postman со всеми API
- Dockerfile и docker-compose корректны, после сборки можно запустить приложение с помощью `docker compose up --build`
- Код чистый и модульный (см. `Архитектурные принципы`)
